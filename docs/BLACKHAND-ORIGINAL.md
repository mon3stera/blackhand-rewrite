## 1. 一句话概括

社交推理游戏（Town of Salem / 狼人杀 类型）：16 名玩家各自拥有**一栋房子**，白天讨论投票处决，夜里**出门去别人家**执行能力；阵营与角色超过 80 种，胜负条件各异，还带银行存档、积分、成就、模型商城等外围系统。

## 2. 一局的时间轴

```
开局：分配角色 → 第 1 天
循环：
  白天（gv_dayLength，默认 1.2 分钟）
    ├─ 播报昨夜死亡（多种死法文案 + 镜头演出）
    ├─ 揭示死者角色 / 遗言（除非被"清理者"清理）
    ├─ 讨论（gv_discussionLength，默认 0.3 分钟）
    ├─ 投票/提名 → 送上审判台
    ├─ 审判：辩护（gv_trialLength 的一半）→ 有罪/无罪投票
    ├─ 处决 / 宽恕
    └─ 判胜检查（gf_CheckEnd）
  夜晚（gv_nightLength，默认 0.6 分钟）
    ├─ "第 N 夜" 播报，关闭白天聊天频道
    ├─ 行动面板开启（按阵营给行动按钮）
    ├─ 行动窗口：nightLength*60 - 20 秒
    ├─ 最后 10 秒提示"夜晚将在 10 秒内结束"
    ├─ 结算：gf_SequencePrep（黑手党投票计票）→ SequenceBullshit → SequenceKills（逐角色结算）→ SequenceAfter → SequenceAfter2
    └─ 判胜检查
```

时长参数（分钟，可由"保存格"覆盖）：

| 参数 | 默认 | 可调范围 |
| --- | --- | --- |
| `gv_dayLength` 白天 | 1.2 | 1.2 – 6.0 |
| `gv_nightLength` 夜晚 | 0.6 | 0.6 – 2.0 |
| `gv_discussionLength` 讨论 | 0.3 | 0.3 – 3.0 |
| `gv_trialLength` 审判 | 0.8 | — |

投票模式（`gv_variant` / 大厅设定）：匿名票决、过半数票决、2 次提名制、开庭（法官）、集体处决（执法长）。

## 5. 夜晚机制

- **行动方式**：每个阵营有行动按钮（`gt_ASActionButtonATown/A/Triad/Neutral` 等），玩家点按钮选目标，提交后写入 `gv_action`。
- **访问**：`gv_visitation[player]` 记录今晚去哪栋房子；多数能力作用于"访问目标"。
- **结算顺序**（`gf_SequencePrep` → `gf_SequenceKills` → `gf_SequenceAfter`）：
  1. 黑手党/三合会**投票计票**（`gv_mafiaKillVotes` / `gv_triadKillVotes`），平票随机、教父/龙头可推翻；
  2. 逐玩家按角色执行能力（控制、保护、调查、击杀、转化……）；
  3. 处理死亡（`deathMethod` 决定死法文案）、免疫消耗、系命连坐、冤魂占据等。
- **特殊交互**：狱警/绑架者监禁并可匿名交谈+处决；保镖代死；退伍军人反杀访客；巴士司机交换两人当晚受到的效果；欺骗者/迷惑藏身转移效果；女巫操纵目标行动；邪教/共济会夜间转化。

## 5.5 房子与"出门访问"的实际实现（重要）

- 全图 **25 个房屋点位**（`gv_houseLocation[25]`），开局给每个玩家随机分配一栋：`gv_playerHouse[p] = RandomInt(0, 24)`。
- 每个玩家有一个角色单位 `gv_unit[p]`，站在 `gv_playerLocation[p]`（自家门口）：
  - 白天：`ShowHideUnit(..., true)` + 显示名字标签 + `UnitSetFacing` 朝向广场；
  - 夜晚：`ShowHideUnit(..., false)` + 隐藏标签。
- **没有实际行走**：`UnitSetPosition` 只用于处决现场（把犯人挪到刑场）；夜间的"去谁家"纯粹是逻辑变量 `gv_visitation[p]`，视觉上靠镜头演出去世地点。
- 结论：**"出门访问"机制的实现成本比看起来低得多**——本质是「每人的房子映射 + 目标选择 + 结算时按访问关系处理」，不需要寻路/移动/碰撞。

## 5.6 夜间行动面板（原图 UI 结构）

`gf_ASInitializeActionDialogs` 为每个存活玩家生成一行（`c_anchorTopRight`，y = 15 + 30*(座位号-1)）：

| 控件 | 尺寸 | 作用 |
| --- | --- | --- |
| 文本 `gv_actionDialogItem[p][1]` | — | 显示该玩家当前票数/目标 |
| 按钮 [2] | 126×30 | 投票（VoteNormal.dds） |
| 按钮 [3] / [4] | 186×48 | 有罪 / 无罪（审判阶段） |
| 按钮 [5] / [6] | 60×30 | 行动 A / 行动 B（x=60 / x=120） |

即：**夜间行动 = 在"玩家列表"上点按钮选目标**，白天投票/审判复用同一套面板（`gv_actionDialog[0]` 行动模式、`[1]` 审判模式）。

## 6. 白天机制

1. **死亡播报**：按 `deathMethod` 给出不同文案（自杀、被爱死、被巴士碾死、被勒死、化为尘埃……），镜头逐个演出去世地点。
2. **揭示与遗言**：死者角色公开（被清理者清理则显示 `???`），公开遗言（`-lw` 指令预设）。
3. **讨论**：`gv_discussionLength`，期间可自由发言。
4. **投票/提名**：按模式计票；平票有"解除僵持"环节；足够票数 → 送上审判台。
5. **审判**：被告辩护（半个 `gv_trialLength`）→ 全员投有罪/无罪 → 有罪多于无罪则处决。
6. **处决**：公开处刑；小丑/处刑者因此达成胜利。
7. **判胜**：每次天亮、投票中、审判结果、处决执行后都会调用 `gf_CheckEnd()`。

## 7. 胜负判定（`gf_CheckEnd` 摘要）

统一经 `gf_EndGame(编号)`。优先检查"某阵营独占"，再检查 2 人残局/平局：

| 编号 | 胜利方 | 条件（简化） |
| --- | --- | --- |
| 1 | 城镇 | 城镇 ≥1 且其他阵营全灭 |
| 2 | 黑手党 | 城镇 0 且黑手党 ≥1 |
| 13 | 三合会 | 城镇 0 且三合会 ≥ 黑手党 |
| 3 | 连环杀手 | 存活且城镇 0 |
| 5 | 生存者 | 存活且城镇 0 且无被处决小丑 |
| 6 | 小丑 | 自己被公开处决且城镇 0 |
| 7 | 女巫 | 存活且城镇 0 |
| 8 | 纵火者 | 存活且城镇 0 |
| 9 | 处刑者 | 目标被公开处决且城镇 0 |
| 10 | 失忆者 | 按转化后的角色判定 |
| 11 | 邪教 | 城镇 0 且邪教 ≥1 |
| 12 | 杀人狂 | 存活且城镇 0 |
| 14 | 审计官 | 存活且城镇 0 |
| 15 | 法官 | 存活且城镇 0 |
